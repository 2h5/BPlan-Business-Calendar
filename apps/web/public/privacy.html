1. Scope

This draft describes the data flows currently represented in the BPlan repository as of September 8, 2026. It is not final and must be reconciled with the deployed services, provider contracts, and the launch jurisdictions.

2. Information processed

  • Account and profile: authenticated account email, name, time zone, clock preference, working hours, and planning defaults.
  • Workspace data: calendars, events, tasks, lists, tags, reminders, recurrence, descriptions, locations, deadlines, and other content entered or imported by the user.
  • Calendar connections: Google or Microsoft account identifiers, email, granted scopes, sync status, and provider metadata. OAuth refresh credentials are stored server-side through Vault references and are not client-readable.
  • Billing: subscription entitlement, status, expiry, provider customer identifier, product/store metadata, and RevenueCat webhook records needed to reconcile access. Checkout is hosted through RevenueCat Billing using Stripe; this repository has no card-entry form.
  • Operations and security: timestamps, stable identifiers, sync/retry state, error codes, webhook outcomes, and account-deletion events needed to operate and secure the service.

3. AI scheduling

When Find Time with AI is enabled for an entitled user, the server sends the configured AI provider the task title, priority, duration, deadline, optional scheduling note, time zone/preferences, and derived candidate-slot features. The current implementation does not send raw event descriptions, locations, attendees, OAuth tokens, or provider credentials to the model. OpenAI requests are configured with storage disabled; the application stores scheduling metadata and suggestions needed for the feature, not full model prompts or provider responses.

4. Services and sharing

Current service flows use Supabase for authentication, database, and server functions; Google and Microsoft when the user connects those calendars; RevenueCat and Stripe for subscription checkout and billing; OpenAI for the configured AI ranker; and Cloudflare Pages for the web application and public pages. Final processor terms and international-transfer details are still a launch-review item.

5. Use of information

BPlan uses this information to authenticate accounts, provide calendar and task features, synchronize connected calendars, determine subscription entitlements, run Find Time when enabled, prevent abuse, troubleshoot failures, and maintain service security.

6. Account deletion and retention

Users can delete their accounts through the current account controls. The implementation revokes connected provider grants before deleting the authenticated user; user-linked product rows are configured to cascade away. The repository does not establish a user-visible backup or third-party retention timetable. Final retention, backup, legal-hold, and processor-deletion language is TBD and must be added before publication as a final policy.
